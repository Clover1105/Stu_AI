# 一、Runnable 接口规范

## （一）why

Runnable 接口规范，就是 LangChain 规定的一套"统一调用标准"，让所有组件都能像插座一样互相连接

若没有Runnable 接口规范，使用不同的组件就要用到不同的调用方式，非常麻烦

因此LangChain 就规定，以后所有组件，都遵守 Runnable 接口规范，无论是谁，都拥有相同的调用方式

## （二）what

很多人看到"接口"两个字就害怕，但其实它不是 Java 里面那个 Interface

这里的接口，可以理解成：大家共同遵守的一套使用说明书，比如USB接口

## （三）where

| 接口      | 同步/异步 | 是否流式 |
| --------- | --------- | -------- |
| invoke()  | 同步      | 否       |
| stream()  | 同步      | 是       |
| ainvoke() | 异步      | 否       |
| astream() | 异步      | 是       |

同步和异步决定程序运行方式；流式决定AI是否一个字一个字输出

## （四）同步和异步的区别

同步：一个任务执行完成后，才能执行下一个任务，阻塞编程

异步：一个任务在等待时，可以先去执行其他任务，非阻塞编程

| 对比项   | 同步     | 异步                           |
| -------- | -------- | ------------------------------ |
| 执行方式 | 顺序执行 | 可并发执行                     |
| 是否等待 | 必须等待 | 不必等待                       |
| 性能     | 较低     | 较高                           |
| 适合场景 | CPU计算  | IO密集型                       |
| 典型应用 | 普通脚本 | 网络爬虫、聊天机器人、AI Agent |

## （五）案例

### 1. 同步

```
import time


def task(name, seconds):
    print(f"任务 {name} 开始，需要 {seconds} 秒")
    time.sleep(seconds)  # 模拟耗时操作（比如读文件、请求网络）
    print(f"任务 {name} 完成")
    return f"结果-{name}"


def main():
    start = time.time()

    # 三个任务依次执行，一个等一个
    result1 = task("A", 2)
    result2 = task("B", 1)
    result3 = task("C", 3)

    print(f"所有结果: {result1}, {result2}, {result3}")
    print(f"总耗时: {time.time() - start:.2f} 秒")


if __name__ == "__main__":
    main()
```

### 2. 异步

```
import asyncio
import time


async def task(name, seconds):
    print(f"任务 {name} 开始，需要 {seconds} 秒")
    await asyncio.sleep(seconds)  # 模拟异步等待（不阻塞）
    print(f"任务 {name} 完成")
    return f"结果-{name}"


async def main():
    start = time.time()

    # 创建三个任务，同时出发
    tasks = [
        asyncio.create_task(task("A", 2)),
        asyncio.create_task(task("B", 1)),
        asyncio.create_task(task("C", 3))
    ]

    # 等待所有任务完成
    results = await asyncio.gather(*tasks)

    print(f"所有结果: {results}")
    print(f"总耗时: {time.time() - start:.2f} 秒")


if __name__ == "__main__":
    asyncio.run(main())
```



# 二、调用接口

## （一）invoke()

**同步调用模型，等待模型全部生成完成以后，一次性返回结果。**

智能体：

```python
from langchain_core.messages import HumanMessage
from model import MyModel
from langchain.agents import create_agent
from tool.SendEmailTool import send_email_tool

"""创建智能体步骤"""
def create_email_agent(que):
    # 1. 创建一个大模型
    model = MyModel.MyModel.get_model()
    # 2. 创建一个工具
    tools = [send_email_tool]
    # 3. 创建提示词 -- 系统提示词
    prompt = """
        -- 角色：你是一个专业的邮件发送助手
    """
    # 4. 创建智能体
    agent = create_agent(
        model, tools,
        system_prompt=prompt,
        debug=True  # 可选，一般用于调试，生成环境必须设置为false
    )
    # 5. 提问
    # 定义一个人类消息类型格式（第一种）
    # human_msg = {"messages":[{"role":"user","content":que}]}
    # 定义一个人类消息类型格式（第二种）
    human_msg = {"messages":[HumanMessage(content=que)]}
    # 6. 回答
    result = agent.invoke(human_msg)    # 非流式输出
    print(result)

if __name__ == '__main__':
    que = "请发送一封邮件给3131355723@qq.com，内容为一段心灵鸡汤"
    create_email_agent(que)
```

## （二）stream()

**同步流式输出**

模型生成一个 Token，程序就立即返回一个 Token

智能体：

```python
from langchain_core.messages import HumanMessage
from model import MyModel
from langchain.agents import create_agent
from tool.SendEmailTool import send_email_tool

"""创建智能体步骤"""
def create_email_agent(que):
    # 1. 创建一个大模型
    model = MyModel.MyModel.get_model()
    # 2. 创建一个工具
    tools = [send_email_tool]
    # 3. 创建提示词 -- 系统提示词
    prompt = """
        -- 角色：你是一个专业的邮件发送助手
    """
    # 4. 创建智能体
    agent = create_agent(
        model, tools,
        system_prompt=prompt,
        # debug=True  # 可选，一般用于调试，生成环境必须设置为false
    )
    # 5. 提问
    # 定义一个人类消息类型格式（第一种）
    # human_msg = {"messages":[{"role":"user","content":que}]}
    # 定义一个人类消息类型格式（第二种）
    human_msg = {"messages":[HumanMessage(content=que)]}
    # 6. 回答
    # result = agent.invoke(human_msg)    # 非流式输出
```

```python
    # 定义一个人类消息类型格式（第二种）
```

### await

调用的时候必须 await 否则不会执行

`await` 是 Python 中用来**等待**一个异步操作（通常是协程或可等待对象）完成的关键字。

它就像是在说：“这里有个耗时任务（比如读文件、请求网络），我先**让出控制权**去干别的，等它完成了再回来继续。”

## （四）astream()

这是企业项目最常用的方法，也是 ChatGPT 的工作方式

**异步 + 流式输出**

特点：不阻塞,Token 实时返回 ,用户体验最好

智能体：

```python
import asyncio
from langchain_core.messages import HumanMessage
from model import MyModel
from langchain.agents import create_agent
from tool.SendEmailTool import send_email_tool

"""创建智能体步骤"""
async def create_email_agent(que):
    # 1. 创建一个大模型
    model = MyModel.MyModel.get_model()
    # 2. 创建一个工具
    tools = [send_email_tool]
    # 3. 创建提示词 -- 系统提示词
    prompt = """
        -- 角色：你是一个专业的邮件发送助手
    """
    # 4. 创建智能体
    agent = create_agent(
        model, tools,
        system_prompt=prompt,
        # debug=True  # 可选，一般用于调试，生成环境必须设置为false
    )
    # 5. 提问
    # 定义一个人类消息类型格式（第一种）
    # human_msg = {"messages":[{"role":"user","content":que}]}
    # 定义一个人类消息类型格式（第二种）
    human_msg = {"messages":[HumanMessage(content=que)]}
    # 6. 回答
    # result = agent.invoke(human_msg)    # 非流式输出
    # stream_mode="messages"：大模型返回的消息流
    async for c,m in agent.astream(human_msg,stream_mode="messages"):
        if c.content:
            yield c.content

# 测试大模型的异步流式输出
async  def test_create_model(que):
    # 创建一个大模型
    model = MyModel.MyModel.get_model()
    # 流式
    async for c in model.astream(input=que):
        if c.content:
            yield c.content

if __name__ == '__main__':
    que = "请发送一封邮件给2920242909@qq.com，内容为一段心灵鸡汤"
    async def test():
        async for i in test_create_model(que):
            print(i,end="")
    asyncio.run(test())
```

### yield

带 `yield` 的函数会自动变为生成器，用 `next()` 调用时，每次执行到下一个 `yield` 处暂停并返回值；若没有更多 `yield`，则会抛出 `StopIteration` 异常。因此推荐使用封装好的 `for` 循环遍历，它会在迭代器耗尽时自动停止，无需手动处理异常。

```
# 复习yield

def func():
    print("start")
    yield 1
    print("end")

if __name__ == '__main__':
    # # 普通迭代
    # rs = func()
    # x = next(rs)
    # print(x)
    # y = next(rs,'')
    # print(y)

    # 循环迭代
    for x in func():
        print(x)
```

### async

带 `async def` 的函数可以理解为**“会主动让座的超级员工”**，它会自动变为协程对象

当你用 `await` 去执行它时，这个员工一旦遇到耗时的活儿（比如网络请求、数据库查询），他不会傻站着干等，而是主动挂起并让出控制权，让系统去处理别的事情；等他需要的结果回来了，系统再叫他回来接着干

因此，推荐使用 `await` 或 `asyncio.gather()` 来调度协程，它们会在任务完成时自动恢复执行，无需你手动管理底层的事件循环

**为什么异步要用 `async` 关键字，而同步不用：**

因为普通的同步函数是“直肠子”，系统默认它会一口气干到底，遇到耗时操作也会傻等，系统没法插手；而加上 `async` 就像给函数贴了个“特权标签”，系统一看就知道：“哦，这个人遇到麻烦事会主动让座”

有了这个标签，系统才会允许他在里面使用 `await` 来挂起和让出控制权。如果不加 `async`，系统就不认识他，自然也就没法帮他自动调度了

### asyncio

如果说 `async` 函数是**“会主动让座的员工”**，那么 `asyncio` 就是那个**“眼观六路、耳听八方的超级大堂经理”**（在专业里，这叫“事件循环 Event Loop”）

**工作流程如下：**

- 员工A遇到需要等待的活儿（比如查数据库），主动让出位置
- 大堂经理（`asyncio`）立刻把员工B叫上来接着干活
- 等员工A需要的结果回来了，大堂经理再安排员工A回到岗位上接着干

### 总结一下

`async` 只是赋予了员工“主动让座”的超能力；而 `asyncio` 是负责统筹全局的“调度中心”

没有 `asyncio` 这个大堂经理在背后不停地安排谁上谁下，员工就算想让座，也没人接手，整个程序还是会卡死

所以，`async` 是**员工的能力**，`asyncio` 是**公司的调度系统**，两者配合，就能在单线程里实现极高的并发效率
