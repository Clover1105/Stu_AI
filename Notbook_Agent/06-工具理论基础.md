# 一、tool

Tool（工具）：在 LangChain 中，**Tool 就是大模型能够调用的一个函数**

可以把 Tool 理解成：给 AI 安装的"外挂能力"

没有 Tool 的时候，大模型只能依靠训练数据回答问题

## （一）为什么需要tool

**虽然GPT 很聪明，但是它不能主动访问外部资源**

所以：Agent负责思考，Tool负责执行

## （二）生命周期

一个 Tool 从创建到执行，大致经历下面几个阶段：

```
定义Tool
↓
注册Tool
↓
Agent加载Tool
↓
LLM决定是否调用
↓
参数生成
↓
执行Tool
↓
返回结果
↓
LLM继续推理
↓
回答用户
```

生命周期：

```
① 用户输入
↓
② LLM分析
↓
③ 选择 send_email_tool
↓
④ 生成参数
{
    "to":"xxx",
    "title":"xxxxx",
    "content":"..."
}
↓
⑤ 调用Tool
↓
⑥ Tool发送邮件
↓
⑦ 返回发送成功
↓
⑧ LLM回复邮件已成功发送
```

整个过程中，真正发送邮件的是 Tool，LLM 并不会自己发送邮件

## （三）组成

一个 Tool 通常包含：

- @tool
- 函数名
- 参数
- DocString
- 返回值

DocString 非常重要，因为 Agent 就是根据 DocString 判断什么时候调用这个 Tool

**Tool 参数可以有很多个**

## （四）args_schema

企业开发中，Tool 参数越来越复杂，如果将所有参数都依次写入函数参数中，代码会越来越乱

因此，LangChain 推荐使用 args_schema，进行参数校验，将参数集中管理

**作用：**参数校验、参数描述、自动生成 JSON Schema、提示 LLM 如何调用

```python
from pydantic import BaseModel,Field
# 定义工具参数校验类
class EmailParams(BaseModel):
    # 收件人
    to:str = Field(...,description="收件人邮箱")
    # 邮件主题
    subject:str = Field(...,description="邮件主题")
    # 邮件内容
    content:str = Field(...,description="邮件内容")
```

Pydantic 参数模型：Pydantic 是 LangChain 使用最广泛的数据验证库

| 对比维度     | 使用 Pydantic (args_schema)              | 不使用 Pydantic                 |
| ------------ | ---------------------------------------- | ------------------------------- |
| 参数验证     | 自动进行类型校验（如 `to` 必须是字符串） | 运行时可能因类型错误崩溃        |
| 参数描述     | 工具文档中会显示清晰的参数说明           | 只显示函数签名，AI 可能理解偏差 |
| 默认值/约束  | 支持 `Field(..., min_length=5)` 等约束   | 无法定义参数约束                |
| AI调用准确性 | 更高（模型知道每个参数的用途）           | 依赖函数命名和文档字符串        |
| 代码可维护性 | 参数结构清晰，易于扩展                   | 参数改动容易引入 bug            |

## （五）规范

| 规范                 | 建议                                                         |
| -------------------- | ------------------------------------------------------------ |
| 一个 Tool 一个职责   | 每个 Tool 只负责一件事情，例如查询数据库、发送邮件、读取文件。 |
| 编写清晰的 DocString | 用自然语言描述 Tool 的功能，帮助 LLM 正确选择工具。          |
| 使用 args_schema     | 参数统一通过 Pydantic 模型管理，便于维护和校验。             |
| Field 描述详细       | 为每个字段提供明确的 `description`，提升参数生成准确率。     |
| 返回统一格式         | 优先返回字符串或 JSON 字符串，便于 Agent 处理。              |
| 完善异常处理         | 使用 `try...except` 捕获异常，避免 Tool 导致整个流程中断。   |

# 二、创建tool

LangChain 推荐使用 `@tool` 装饰器

```python
from langchain.tools import tool

# 定义工具
@tool(
    "send_email_tool",  # 可选，默认用对应方法名作为工具名称
    description="发送邮件工具",
    args_schema=EmailParams,
)
def send_email_tool(to:str,subject:str,content:str)->str:
    """
    用于发送邮件，发送通知，发送信息
    """
    # 每个工具都要加异常处理
    try:
        # 读取配置文件信息
        email = os.getenv("SENDER_EMAIL")   # 发件人邮箱
        host = os.getenv("EMAIL_HOST")
        port = os.getenv("EMAIL_PORT")
        password = os.getenv("SENDER_EMAIL_PASSWORD")
        # 判断配置是否读取成功
        if not email or not host or not port or not password:
            raise Exception("配置文件信息读取失败")
        # 创建邮件对象
        msg = MIMEText(content)
        msg['To'] = to  # 收件人
        msg['Subject'] = subject    # 邮件主题
        msg['From'] = email  # 发件人
        # 创建一个链接邮件服务器地址
        with smtplib.SMTP_SSL(host,int(port)) as smtp:  # port读取出来为字符串，需要转换为int
            # 登录邮件服务器
            smtp.login(email,password)
            # 发送邮件
            smtp.sendmail(email,to,msg.as_string())
        return "发送邮件成功\n"
    except Exception as e:
        print(f"发送邮件失败:{e}")
        return f"发送邮件失败:{e}"
```

# 三、Agent调用外部RESTful API

**RESTful API**（Representational State Transfer）是一种基于HTTP协议的API设计风格，广泛应用于Web服务的集成。通过RESTful API，客户端可以通过HTTP请求与服务器进行交互，获取数据或提交数据

在LangChain中集成API，可以通过自定义工具来封装API的请求，使得Agent能够轻松与外部服务进行通信

## （一）集成外部API的基本步骤

1. **获取API访问权限**：
    - 通常你需要从第三方服务获取API密钥，或者注册开发者账号来获得API访问权限。
2. **编写API调用代码**：
    - 使用`requests`库来发送HTTP请求，获取API响应。
    - 使用`json`库来解析API响应。
3. **定义Tool**：
    - 使用`@tool`装饰器来将API调用封装成一个工具，让LangChain Agent能够调用它

## （二）集成外部API的详细流程

1. 在你的环境中安装`requests`库，用于API调用：

```
pip install requests
```

2. 创建API调用工具：

高德驾车路线规划一般通过经纬度坐标来查询，先自定义一个函数来根据地点获取经纬度坐标

```python
import requests
from dotenv import load_dotenv
import os
load_dotenv()

# 根据地点获取地理编码
def get_geocode(address):
    # 定义地址
    url = os.getenv("GAODE_GEO_URL")
    # 定义参数（字典）
    params = {
        "key": os.getenv("GAODE_AMAP_KEY"),
        "address": address
    }
    r = requests.get(url=url, params=params)
    # 格式转换
    r = r.json() # 需要的字段：location
    # 提取需要的内容
    location = r["geocodes"][0]["location"]
    return location

if __name__ == '__main__':
    get_geocode("北京市海淀区中关村大街1号")
```

定义一个驾车路线规划工具

```python
import asyncio
from langchain_core.messages import HumanMessage
from model import MyModel
from langchain.agents import create_agent
from tool.SendEmailTool import send_email_tool
from tool.add_toll import AddToll
from tool.amap_driver_tool import AmapDriverTool
from prompt.builder_prompt_yaml import BuilderPromptYaml

"""创建智能体步骤"""
async def send_email_agent(que):
    # 1. 创建一个大模型
    model = MyModel.MyModel.get_model()
    # 2. 创建一个工具
    tools = [send_email_tool,AddToll,AmapDriverTool]
    # 3. 创建提示词 -- 系统提示词
    prompt = BuilderPromptYaml.get_prompt("send_email_agent.yaml")
    # 4. 创建智能体
    agent = create_agent(
        model=model, tools=tools,
        system_prompt=prompt,
        debug=True  # 可选，一般用于调试，生成环境必须设置为false
    )
    # 5. 提问
    # 定义一个人类消息类型格式（第一种）
    # human_msg = {"messages":[{"role":"user","content":que}]}
    # 定义一个人类消息类型格式（第二种）
    human_msg = {"messages":[HumanMessage(content=que)]}
    # 6. 回答
    result = await agent.ainvoke(human_msg)    # 非流式输出
    print(f"*-*-*-{result}")
    print(result["messages"][-1].content)


if __name__ == '__main__':
    que = "开车从重庆北站到成都东站怎么走？"
    # 异步调用
    asyncio.run(send_email_agent(que))
```
