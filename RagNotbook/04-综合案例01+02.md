# 一、基于 LangChain + Chroma + RetrievalQA 实现 RAG 问答系统

使用langchain封装的问答链PetrievalQA实现

注意：langchain封装的API和chroma库中的API不一样，不要混淆

安装库：`pip install langchain-chroma==1.1.0`

拓展知识（先了解即可）：若使用 langchain 中的技术将各各模块搭建起来，那么每一个模块的类型都要是 runable 结构

## （一）案例整体流程

本案例使用 **LangChain** 对 RAG（Retrieval-Augmented Generation，检索增强生成）进行了完整封装，实现了一个能够基于本地知识库进行智能问答的系统。

### 1. 整体流程

【 项目配置 ==> 初始化大语言模型（LLM） ==> 读取原始文档 ==> 文本切分 ==> Embedding 向量化 ==> 创建 Chroma 向量数据库 ==> 加载向量数据库 ==> 普通LLM问答（无RAG） ==> RetrievalQA（检索→生成） ==> 输出最终答案 】

**langchain封装chromadb的API实现流程**：

- 构造向量数据库数据内容
    - 加载数据
    - 数据分块
    -  加载向量化模型
    -  创建向量数据库然后存入数据【创建向量数据库的时候直接指定存储路径和集合名称】
- 问答 --- 外部知识库数据的查询结果作为上下文，然后模型生成回复
    - 加载向量数据库
    - 加载大模型、向量化模型
    - 得到向量数据库对象、创建问答链
    - 生成回复【本质上通过问答链来完成的，不是直接用大模型生成回复，大模型这个时候已经放在langchain的链里面去了，它会自动的去检索当前问题相关的文档，然后基于相关的文档【模型回复上下文】来回答当前的问题】

### 2. 步骤：

- 项目配置：
    - 原始文档路径、ChromaDB 数据库持久化存储路径、ChromaDB 集合名称、LLM 模型名称（用于生成回答）
- 创建向量数据库并且添加数据 -- 处理文档
    - 导包：TextLoader、RecursiveCharacterTextSplitter
    - 加载器读取文本、加载数据、创建分割对象、分割文本
- 创建向量数据库并且添加数据 -- 加载向量化模型（本地）
    - 导包：HuggingFaceEmbeddings
    - 在项目配置中添加向量模型本地存储路径
    - 实现本地要添加参数：model_kwargs={"device": "cuda","local_files_only": True,}
- 创建向量数据库并且添加数据 -- 创建向量数据库
    - 导包：Chroma
    - 参数：数据内容、向量化模型、存储位置、集合名称、相似度匹配方式
    - 防止出问题报错，可以使用try...except...方法
- 查询向量数据库中的数据
    - Chroma 方法（集合名称，数据库路径）
- 初始化大语言模型
    - 导包：ChatOpenAI、os
    - -- ChatOpenAI()
    - 非流式 -- invoke()
- 问答：不使用RAG
    - 设置：系统和角色信息，调用llm生成回复，打印回复（get方法）
    - 存在幻觉问题
- 问答：使用RAG
    - -- 先用 langchain 封装的QA链实现
    - 导包：RetrievalQA
    - 初始化向量化模型（和创建时的模型一致）、创建向量数据库对象、调用QA链、通过QA链生成回复
- 执行，调用函数

【注意】—— 记得导包

## （二）项目配置

首先配置整个项目需要使用的各种资源。

包括：

- 原始知识文档 -- `txt_path`
- ChromaDB 数据库存储位置 -- `vector_path`
- Collection 名称 -- `collection_name`
- Embedding 模型 -- `model_name`
- Embedding 本地模型路径 -- `model_path`

其中：

**txt_path** -- 用于指定需要建立知识库的原始文本；后续整个知识库的数据都来自这里。

**vector_path** -- 指定 Chroma 数据库存放的位置；第一次运行时会自动创建，以后再次运行不会重新创建，而是直接读取。

**collection_name** -- 一个数据库可以有很多 Collection，这里实际上指定的是，当前知识库叫什么名字。

**model_name** -- 记录当前使用的是哪个 Embedding 模型；虽然本案例真正加载的是本地模型，但是保留模型名称能够方便以后切换。

**model_path** -- 真正加载模型的位置；由于后面设置了`local_files_only=True`因此程序不会联网下载模型。

```python
# 原始文档路径
txt_path = r"G:\GitHub\Stu_AI\StuRAG\datasets\测试.txt"
# ChromaDB 数据库持久化存储路径
vector_path = r"G:\GitHub\Stu_AI\StuRAG\chromadb_data"
# ChromaDB 集合名称
collection_name = "an_li01"
# Embedding 模型名称
model_name = "sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2"
# Embedding 模型本地存储路径
model_path = r"G:\models\paraphrase-multilingual-MiniLM-L12-v2"
# model_name 用于指定 Hugging Face 模型名称；
# model_path 用于指定本地模型路径，本项目使用本地模型，因此实际加载的是 model_path。
```

## （四）创建向量数据库

### 1. 加载原始文档

使用加载器`TextLoader`读取文本，返回`Document`对象。

里面除了正文之外，还保存了：

- metadata
- source
- 文件路径

这样，以后检索时还能知道，答案来自哪个文件

```python
from langchain_community.document_loaders import TextLoader

# 创建加载器对象
loader = TextLoader(file_path=txt_path, encoding="utf-8")

# 加载数据
txt = loader.load()
```

### 2. 文本切分

文本不能直接向量化：

- 模型存在 Token 长度限制
- 一个向量如果内容过多，语义会变得非常模糊。

所以，使用分割器`RecursiveCharacterTextSplitter`对文本进行切分

```python
from langchain_text_splitters import RecursiveCharacterTextSplitter

# 创建分割对象
txt_fg = RecursiveCharacterTextSplitter(
    # 每块最多 100 个字符，相邻两块重复 20 个字符。
	chunk_size=100, # 块大小
	chunk_overlap=20,   # 块重叠大小
	length_function=len,    # 计算块的长度
	separators=["\n\n", ".", "？", "！", "\n"]    # 分割符号
)

# 分割文本
txt_list = txt_fg.split_documents(txt)
```

### 3. 初始化 Embedding 模型

使用`HuggingFaceEmbeddings`加载本地模型

`device="cuda"` -- 使用 GPU 推理，如果没有 GPU，可以改成CPU

`local_files_only=True` -- 只读取本地模型，不会联网下载，这样可以避免网络问题导致加载失败。

```python
from langchain_huggingface import HuggingFaceEmbeddings

embedding_model = HuggingFaceEmbeddings(
	model_name=model_path,
    # 使用本地模型
    model_kwargs={
    	"device": "cuda",
        "local_files_only": True,
    },
)
```

### 4. 创建 Chroma 向量数据库

LangChain 提供了一个非常方便的方法：`Chroma.from_documents(...)`

可以一步完成：Document、Embedding、生成向量、保存数据库

无需自己调用：`collection.add()`，整个过程已经封装好了

主要参数：

- `documents` -- 表示需要存入的数据。
- `embedding` -- 指定向量模型。后续所有查询必须使用同一个模型，否则无法计算相似度。
- `persist_directory` -- 指定数据库保存位置。
- `collection_name` -- 指定集合。
- `collection_metadata` -- 指定 `"hnsw:space":"cosine"` ，使用余弦相似度，这是文本检索最常见的方式。

整个创建过程放到了：`try...except...` 里面，避免数据库创建失败导致程序直接崩溃。

```python
from langchain_chroma import Chroma

try:
    Chroma.from_documents(
        documents=txt_list, # 数据内容
        embedding=embedding_model,  # 向量化模型
        persist_directory=vector_path,  # 数据库持久化存储路径
        collection_name=collection_name,    # 集合名称
        collection_metadata={"hnsw:space":"cosine"} # 相似度匹配
    )
    print("向量数据库创建成功")
except Exception as e:
    print(f"向量数据库创建失败{e}")
```

### 5. 封装

```python
def build_vector_db():
    """ 加载器"""
    # 创建加载器对象
    loader = TextLoader(file_path=txt_path, encoding="utf-8")
    # 加载数据
    txt = loader.load()

    """ 分割器 """
    # 创建分割对象
    txt_fg = RecursiveCharacterTextSplitter(
        chunk_size=100, # 块大小
        chunk_overlap=20,   # 块重叠大小
        length_function=len,    # 计算块的长度
        separators=["\n\n", ".", "？", "！", "\n"]    # 分割符号
    )
    # 分割文本
    txt_list = txt_fg.split_documents(txt)

    """ 初始化 Embedding 模型 """  # 设置全部通过本地地址加载
    embedding_model = HuggingFaceEmbeddings(
        model_name=model_path,
        # 使用本地模型
        model_kwargs={
            "device": "cuda",
            "local_files_only": True,
        },
    )

    """ 创建 Chroma 向量数据库并写入文档 """   # 一步到位，直接就把数据存入到了向量数据库中
    try:
        Chroma.from_documents(
            documents=txt_list, # 数据内容
            embedding=embedding_model,  # 向量化模型
            persist_directory=vector_path,  # 数据库持久化存储路径
            collection_name=collection_name,    # 集合名称
            collection_metadata={"hnsw:space":"cosine"} # 相似度匹配
        )
        print("向量数据库创建成功")
    except Exception as e:
        print(f"向量数据库创建失败{e}")
```

## （五）查询向量数据库

数据库创建完成以后，可以重新连接：`vector_db = Chroma(...)`

这里只需要：Collection、数据库存放位置，即可连接已有数据库。

然后：`vector_db.get()`

即可查看：id、document、metadata，验证数据是否已经成功写入。

用函数进行封装方便后期调用

```python
def chaxun_vector_da():
    # 创建（连接）Chroma 向量数据库对象
    # 并连接指定的 Collection（集合）
    vector_db = Chroma(
        collection_name = collection_name,
        persist_directory = vector_path
    )
    # get()：获取当前集合中的全部数据
    print(vector_db.get())
```

## （六）不使用 RAG 的问答

为了体现 RAG 的作用，案例先进行了普通问答。

流程非常简单：

- System Prompt ==》 User Prompt ==》 LLM ==》 回答

调用非流式方法：`chatLLM.invoke(messages)`，即可生成答案

这种方式完全依赖模型自身知识，如果模型不知道，就可能：编造事实、回答错误、出现幻觉

因此并不能回答知识库中的私有内容。

```python
from langchain_classic.chains.retrieval_qa.base import RetrievalQA

def no_rag():
    messages = [
        # 系统角色提示
        {"role": "system", "content": "你是一个专业的学校百科全书，什么都知道"},
        # 用户问题
        {"role": "user", "content": "重庆三峡学院正式更名为重庆三峡大学？"}
    ]
    # LangChain 中调用大语言模型（LLM）生成回复的方式
    rs = chatLLM.invoke(messages)
    print(rs.content)
```

## （七）使用 RAG 进行问答

这里先用 langchain 封装的QA链实现

流程如下：

- 问题 ==> Retriever ==> 向量检索 ==> 返回相关Chunk ==> LLM ==> 最终答案


相比普通问答，最大的区别就是：

- LLM 在回答之前，先获得了一批与问题最相关的知识,因此回答更加准确。

### 1. 再次初始化 Embedding

这里需要重新创建：`HuggingFaceEmbeddings`

原因不是重新训练模型：

- 而是：查询时也需要把用户的问题转换成向量，因此必须拥有同一个 Embedding 模型
- 并且：必须与建立数据库时完全一致
- 否则：问题向量与文档向量不在同一个向量空间，无法正确计算相似度

```python
# 初始化 Embedding 模型（与创建向量数据库时保持一致）
embedding_model = HuggingFaceEmbeddings(
    model_name=model_path,
    # 使用本地模型
    model_kwargs={
        "device": "cuda",
        "local_files_only": True,
    },
)
```

### 2. 加载 Chroma

创建数据库时，使用的是：`from_documents()`

这里已经存在数据库，所以直接：`Chroma(...)`即可连接

与创建数据库相比，这里多了一个参数：`embedding_function`

作用就是：查询时用于向量化用户问题

```python
# 创建（连接）Chroma 向量数据库对象
vector_db = Chroma(
    collection_name = collection_name,  # 集合名称
    persist_directory = vector_path,    # 数据库持久化存储路径
    embedding_function=embedding_model  # 指定模型
)
```

### 3. 创建 RetrievalQA

这一句：`RetrievalQA.from_chain_type(...)`是整个案例最重要的一句

它把：LLM + Retriever + Prompt + 文档拼接 + 最终回答，全部封装好了

开发者只需要提供：llm，以及：retriever，即可

真正体现了 LangChain 的链式思想

### 4. 创建 Retriever

`vector_db.as_retriever(...)` -- 把 Chroma 和 Retriever 进行了转换，因为QA 链需要的是 Retriever，而不是数据库对象

指定`k=3` -- 表示检索最相关的三个 Chunk

随后，QA 链会把这三个 Chunk一起发送给 LLM

```python
from langchain_classic.chains.retrieval_qa.base import RetrievalQA

# 创建 QA 链（RAG 问答链）
# 将大语言模型（LLM）和向量数据库（Retriever）组合起来，
# 构建一个能够"先检索知识，再生成回答"的问答系统。
qa_chain = RetrievalQA.from_chain_type(
    llm=chatLLM,  # 大语言模型（LLM）
    # 检索器，这个检索出来的结果就是召回，通常10-30条数据
    retriever=vector_db.as_retriever(search_kwargs={"k": 3}),  # 由 Chroma 转换得到的检索器
    return_source_documents=True  # 是否返回检索到的原始文档（可选），字典
)
```

### 5. 调用 QA 链

最后：`qa_chain.invoke(question)`

整个流程自动完成：

- 问题 ==> Embedding ==> Retriever ==> Top3 ==> Prompt ==> LLM ==> 最终答案

返回的数据是一个字典

其中：`rs["result"]` 就是最终回答

如果：`return_source_documents=True`，还会返回所有参与回答的原始文档，方便查看模型引用了哪些知识

```python
# 调用 QA 链执行问答
# QA 链会先检索相关文档，再结合检索结果生成最终回答。
rs = qa_chain.invoke(question)

# 输出模型生成的回答
print(rs["result"])
```

### 6. 封装

```python
    )

    # 创建 QA 链（RAG 问答链）
    # 将大语言模型（LLM）和向量数据库（Retriever）组合起来，

```



## （八）程序执行流程

主函数中，可以根据需要选择执行不同功能。

- `build_vector_db()` -- 首次运行，建立知识库，通常只需要执行一次
- `chaxun_vector_da()` -- 查看数据库内容，用于验证是否写入成功

```python
if __name__ == "__main__":
```

# 二、基于 LangChain Runnable 自定义 RAG 问答链

## （一）案例整体流程

### 1. 整体流程

【 项目配置 ==> 初始化大语言模型（LLM） ==> 加载向量化模型 ==> 加载 Chroma 向量数据库 ==> 创建 Retriever（检索器） ==> 构建 PromptTemplate ==> 构建 Runnable Chain（Retriever + Prompt + LLM） ==> 调用 Chain 完成 RAG 问答 ==> 输出结果（伪流式）】

**LangChain Runnable 自定义 RAG Chain 实现流程：**

- 构造 RAG 问答链
    - 加载向量化模型
    - 加载向量数据库
    - 获取 Retriever（检索器）
    - 编写 PromptTemplate（系统提示词）
    - 构建 Runnable Chain
        - 检索知识（Retriever）
        - 打印召回文档（RunnableLambda）
        - 原样传递用户问题（RunnablePassthrough）
        - PromptTemplate 替换变量
        - ChatOpenAI 生成回答
        - StrOutputParser 输出字符串
- 问答 --- 外部知识库数据的查询结果作为上下文，然后模型生成回复
    - 调用 Chain（invoke）
    - Chain 自动完成：检索 → Prompt 拼接 → LLM 回复 → 输出解析
    - 最终返回字符串结果，然后通过伪流式方式逐字输出
    - 整个过程中无需手动调用 Retriever、Prompt、LLM，它们已经全部封装在 Runnable Chain 中

### 2. 步骤：

- 项目配置
    - ChromaDB 数据库持久化存储路径
    - ChromaDB 集合名称
    - Embedding 模型名称
    - Embedding 模型本地存储路径
- 初始化大语言模型
    - 导包：ChatOpenAI、os
    - ChatOpenAI()
- 加载向量化模型
    - 导包：HuggingFaceEmbeddings
    - 使用本地 Embedding 模型
    - 参数：`model_kwargs={"device":"cuda","local_files_only":True}`
- 加载向量数据库
    - 导包：Chroma
    - 参数：集合名称、数据库持久化路径、Embedding 模型
- 创建检索器（Retriever）
    - `vector_db.as_retriever()`
    - 设置检索参数 `search_kwargs={"k":2}`
- 构建 PromptTemplate
    - 导包：PromptTemplate
    - 编写系统提示词模板
    - 设置变量：`context`、`question`
- 构建 Runnable Chain
    - 导包：RunnableParallel、RunnableLambda、RunnablePassthrough、StrOutputParser
    - RunnableParallel：同时准备上下文和问题
    - Retriever：检索相关文档

- 输出结果

    - 配合 `time.sleep()` 实现逐字打印效果

### 1. 加载 Embedding 模型

随后创建：`vector_db = Chroma(...)`

这里不会创建数据库,而是连接已经存在的 Collection。

相比案例一，这里多了：`embedding_function=embedding_model`

作用就是：以后 Retriever 在查询时，直接调用这个 Embedding 把问题转换成向量。


### 3. 创建 Retriever（检索器）

数据库本身不能直接参与 Chain，因此首先需要转换成 Retriever。

```python
retriever = vector_db.as_retriever(
    search_kwargs={"k":2}
```

这里指定：`k=2`，表示每次检索最相似的两个 Chunk。

- 用户问题 ==> Embedding ==> 向量检索 ==> Top2 文档

Retriever 的作用就是：把向量数据库封装成统一的检索接口。

以后无论底层使用：

- Chroma
- FAISS
- Milvus

都可以通过 Retriever 统一调用。

### 4. 构建 PromptTemplate

检索结束以后，需要把**检索内容和用户问题**，一起交给 LLM，因此需要 Prompt。

这里定义了一份完整的系统提示词。

```python
# 设置大模型回复的提示词 -- 属于系统提示词
# 比如下面的template就是提示词内容，其中{xxxx}表示一个变量，在提示词使用的过程中会被替换为实际的值
template = """
    你是一名知识库问答助手，请结合提供的知识内容回答用户问题。
    回答要求：
        - 仅依据提供的知识内容进行回答，不补充未出现的信息。
        - 若知识内容无法回答问题，请明确说明当前知识不足，避免推测或编造。
        - 对多个知识片段进行综合分析后再作答，避免简单复制原文。
        - 回答应准确、自然、条理清晰，优先直接回答问题，再补充必要说明。
        - 相同信息无需重复描述。
        - 不要提及"根据参考资料"、"根据检索结果"、"根据上下文"等描述。
        - 若未提供任何知识内容或知识为空，请友好告知暂时无法回答，并建议用户补充信息或换个问题。
    知识内容：
        {context}
    用户问题：
        {question}
    回答：
"""
```

- `{context}` -- 表示检索出来的知识，稍后由 Retriever 自动替换。
- `{question}` -- 表示用户的问题，最终也会自动替换。

PromptTemplate 创建：

```python
from langchain_core.prompts import PromptTemplate

#创建提示词对象
prompt = PromptTemplate(
    template=template,
    input_variables=["context", "question"],
)
```

这里只指定两个变量：context、question

说明：后面的 Chain 必须提供这两个字段，否则 Prompt 无法格式化。

### 5. 打印召回结果

案例中定义了`print_doc()`，作用非常简单

- 遍历 Retriever 返回的所有 Document。

打印`doc.page_content`是为了方便观察Retriever 究竟召回了哪些知识。

最后`return docs`一定要返回，否则，后面的 Chain 就接收不到检索结果。

因此，这个函数既承担调试输出，又承担继续向后传递数据。

```python
# 打印召回的结果
def print_doc(docs):
    print("\n检索到的文档内容：")
    # 遍历docs获取每一条检索到的文档信息
    for doc in docs:
        print(doc.page_content)
        print("-" * 20)
    # 返回检索结果给后续使用
    return docs
```

### 6. 使用 Runnable 构建 Chain

自己构建langchain中的链（chain）来实现RAG问答，步骤：

- 加载向量化模型
- 加载向量数据库对象
- 明确自己的链的执行过程：
    - 获取向量数据库的检索结果，把检索的结果和问题一同打包，替换大模型提示词中的变量占位符
    - 在使用llm生成回复
    - 输出结果的处理，比如可以把llm输出的结果转为字符串输出等等...

想要构建langchian中的链，其实就是搭积木，要求每一个积木实现runnable接口，如果说在搭建chain的过程中，需要把一个函数

转为可以放入到chain中使用的积木，那么可以直接把函数放在RunnableLambda中直接转换

这一部分是整个案例**最重要的内容**，整个 Chain：

```python
from langchain_core.runnables import RunnableParallel
from langchain_core.runnables import RunnableLambda
from langchain_core.runnables import RunnablePassthrough
from langchain_core.output_parsers import StrOutputParser

qa_chain = (
    RunnableParallel(    # 并行执行器
        {
            # RunnableLambda的作用就是把普通函数print_docs转换为chain的对象【实现了runnable接口，就可以放入到chain中】
            # retriever的输出就是print_docs函数中的型参输入 --- 等价于doces=检索的文档
            "context": retriever | RunnableLambda(print_doc),   # 上下文，内容就是检索器的结果，直接创建一个检索器即可
            "question": RunnablePassthrough(),  # 透明传递，直接使用question变量的值【不做任何更改】
        }
    )
    # “ | ”表示管道运算符
    | prompt  # 提示词
    | chatLLM  # 大模型对象
    | StrOutputParser()  # 把chatllm输出的结果转为字符串输出
)
```

- `RunnableParallel()` -- 并行执行多个 Runnable，`{"context": ...,"question": ...}`表示同时准备 Prompt 所需的两个变量，最后一起组成传递给 Prompt
- context 分支
    - `retriever | RunnableLambda(print_doc)`
    - 流程：问题 ==> Retriever ==> Document ==> print_doc() ==> Document
    - Retriever 返回Document 列表，随后通过`RunnableLambda()`把普通 Python 函数`print_doc`转换成Runnable 这样它才能加入 Chain
    - 运行过程中，不仅打印召回结果，还会继续返回Document，因此不会影响后续流程

- question 分支
    - `RunnablePassthrough()`
    - 作用非常简单，什么都不做，直接把：question 继续向后传递，即：输入 ==》原样输出
    - 它主要用于：Prompt 中 {question} 变量赋值。

实际上就是：把很多 Runnable 用管道连接起来。

整个执行顺序如下：

【用户问题 ==> RunnableParallel ==> a. ==> Retriever ==> 打印召回结果 ==> d. ==> 原始问题 ==> a.b.并行 ==> PromptTemplate ==> ChatOpenAI ==> StrOutputParser ==> 字符串结果 ==> 伪流式输出】

每一步都会接收上一层输出，再交给下一层，真正体现了 LangChain 的流水线思想。

### 7. 调用 PromptTemplate

RunnableParallel执行结束以后。

得到：

```python
{
    "context": docs,
    "question": question
}
```

随后进入：prompt

PromptTemplate 自动把：

- {context} 替换成：Retriever 返回的文档。
- {question} 替换成：用户问题。

最终生成：真正发送给大模型的 Prompt。

### 8. 调用 ChatOpenAI

随后 chatLLM 接收 Prompt 开始调用：Qwen。

最终得到：AIMessage。

这里输出仍然不是字符串，而是 LangChain 的消息对象。

### 9. 调用 StrOutputParser

因此继续经过：StrOutputParser() 把 AIMessage 转换成字符串

最终：rs就是普通字符串

方便：打印、保存、或者继续处理

### 10. 调用 Chain

整个 Chain 已经搭建完成，最后只需要调用即可：

```python
# 调用 QA 链
rs = qa_chain.invoke(question)
```

整个流程由 LangChain 自动调度，开发者无需手动调用每一步。

### 11. 伪流式输出

最后没有直接：`print(rs)`

而是：模拟流式输出。

```python
import time

# 伪造流式输出
s = ""
print("输出结果：")
for item in rs:
	s += item
	print("\r" + s, end="", flush=True)

```

执行过程如下：

- 第一次：你
- 第二次：你好
- 第三次：你好，
- 第四次：你好，我
- ……

每次都覆盖上一行。

因此看起来像：ChatGPT 的逐字输出效果。

实际上：LLM 已经一次性返回完整结果。

这里只是：人为模拟 Streaming。

```python
from langchain_core.runnables import RunnablePassthrough
# 转为字符串输出
from langchain_core.output_parsers import StrOutputParser
# 将普通函数转为转换为chain的对象
from langchain_core.runnables import  RunnableLambda
# 时间
import time

""" 项目配置 """
# ChromaDB 数据库持久化存储路径
vector_path = r"G:\GitHub\Stu_AI\StuRAG\chromadb_data"
# ChromaDB 集合名称
collection_name = "an_li01"
# Embedding 模型名称
model_name = "sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2"
# Embedding 模型本地存储路径
model_path = r"G:\models\paraphrase-multilingual-MiniLM-L12-v2"

""" 初始化大语言模型 """
chatLLM = ChatOpenAI(
    api_key=os.getenv("DASHSCOPE_API_KEY"),
    base_url="https://dashscope.aliyuncs.com/compatible-mode/v1",
    model="qwen3.7-max",

""" 问答：使用RAG """    # 先用langchain封装的QA链实现
def yes_rag_qa(question):
    # 初始化 Embedding 模型（与创建向量数据库时保持一致）
    embedding_model = HuggingFaceEmbeddings(
        model_name=model_path,
        # 使用本地模型
        model_kwargs={
            "device": "cuda",
            "local_files_only": True,
        },
    )

    # 创建（连接）Chroma 向量数据库对象
    vector_db = Chroma(
        collection_name = collection_name,  # 集合名称
        persist_directory = vector_path,    # 数据库持久化存储路径
        embedding_function=embedding_model  # 指定模型
    )

    # 获取检索器
    retriever = vector_db.as_retriever(search_kwargs={"k": 2})

    # 设置大模型回复的提示词 -- 属于系统提示词
    # 比如下面的template就是提示词内容，其中{xxxx}表示一个变量，在提示词使用的过程中会被替换为实际的值
    template = """
    你是一名知识库问答助手，请结合提供的知识内容回答用户问题。
    回答要求：
        - 仅依据提供的知识内容进行回答，不补充未出现的信息。
        - 若知识内容无法回答问题，请明确说明当前知识不足，避免推测或编造。
        - 对多个知识片段进行综合分析后再作答，避免简单复制原文。
        - 回答应准确、自然、条理清晰，优先直接回答问题，再补充必要说明。
        - 相同信息无需重复描述。
        - 不要提及"根据参考资料"、"根据检索结果"、"根据上下文"等描述。
        - 若未提供任何知识内容或知识为空，请友好告知暂时无法回答，并建议用户补充信息或换个问题。
    知识内容：
        {context}
    用户问题：
        {question}
    回答：
    """

    #创建提示词对象
    prompt = PromptTemplate(
        template=template,
        input_variables=["context", "question"],
    )

    # 打印召回的结果
    def print_doc(docs):
        print("\n检索到的文档内容：")
        # 遍历docs获取每一条检索到的文档信息
        for doc in docs:
            print(doc.page_content)
            print("-" * 20)
        # 返回检索结果给后续使用
        return docs

    qa_chain = (
        RunnableParallel(    # 并行执行器
            {
                # RunnableLambda的作用就是把普通函数print_docs转换为chain的对象【实现了runnable接口，就可以放入到chain中】
                # retriever的输出就是print_docs函数中的型参输入 --- 等价于doces=检索的文档
                "context": retriever | RunnableLambda(print_doc),   # 上下文，内容就是检索器的结果，直接创建一个检索器即可
                "question": RunnablePassthrough(),  # 透明传递，直接使用question变量的值【不做任何更改】
            }
        )
        # “ | ”表示管道运算符
        | prompt  # 提示词
        | chatLLM  # 大模型对象
        | StrOutputParser()  # 把chatllm输出的结果转为字符串输出
    )

    # 调用 QA 链
    rs = qa_chain.invoke(question)

    # 伪造流式输出
    s = ""
    print("输出结果：")
    for item in rs:
        s += item
        print("\r" + s, end="", flush=True)
        time.sleep(0.1)
    print()

if __name__ == "__main__":
    # 问答：使用RAG
    question = input("请输入问题：\n")
    yes_rag_qa(question)
```
