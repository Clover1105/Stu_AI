# 一、FlagEmbedding

## （一）什么是 FlagEmbedding

### 1. 定义

在前面的学习中，我们已经接触了 **Embedding（文本向量化）**。无论是构建向量数据库、语义检索，还是 RAG，第一步都是将文本转换为计算机能够理解的向量。

**FlagEmbedding** 就是专门完成这项工作的工具库，专注于**文本向量化（Embedding）**。

它由 **FlagOpen（智源研究院）** 开源，集成了高质量的文本向量模型（BGE 系列）和重排序模型（Reranker），不仅能够完成文本向量化，还能够完成语义检索、相似度计算以及检索结果重排序，是目前 RAG 开发中最常用的 Embedding 工具之一。

整个流程可以理解为：

文本 \==> FlagEmbedding（Embedding模型） \==> 文本向量（Embedding） \==> 向量数据库 \==> Embedding 检索（召回 Top-K） \==> Reranker 重排序 \==> 最相关文档 ==> LLM 生成答案

可以看到，**FlagEmbedding 不只是一个 Embedding 库，它几乎覆盖了整个 RAG 检索阶段的大部分工作。**

### 2. FlagEmbedding 在 RAG 中的位置

一个完整的 RAG 工作流程如下：

- 用户提问 ==》 Query 向量化 ==》 向量数据库相似度搜索 ==》召回 Top-K 文档 ==》 Reranker 精排 ==》 LLM 回答

其中：

- **Embedding 模型**
    - 负责把 Query 和文档转换成向量。
    - 追求的是**速度**，能够快速从海量数据中找到可能相关的文档。
- **Reranker 模型**
    - 对召回出来的少量文档再次计算相关性。
    - 追求的是**准确率**，保证最终送给大模型的文档质量最高。

因此：

> **Embedding 负责"找"，Reranker 负责"排"，LLM 负责"答"。**

### 3. 主要功能

**（1）文本向量化（Embedding）**：

将文本转换成高维向量。

例如："苹果公司由乔布斯创立" ==》[-0.15,0.32,0.61,...]

生成向量后，就可以：

- 保存到向量数据库
- 计算文本相似度
- 进行语义搜索
- 构建 RAG 知识库

因此，它是整个 RAG 的第一步。

**（2）语义检索（Semantic Search）**：

传统搜索：关键词是否一样？

语义搜索：意思是否相近？

例如：

- 知识库：苹果公司由乔布斯创立。
- 用户提问：苹果是谁创建的？

虽然没有完全相同的文字，但是语义一致，因此仍然能够检索出来，这也是 Embedding 最大的优势。

**（3）Reranker（重排序）**：

Embedding 检索追求的是：**速度快、召回率高**

因此它只负责：从几万甚至几百万条数据中，快速找出 Top-K

但是：Top-K 不一定排序最准确。

例如：

```
Query：
什么是 RAG？
```

Embedding 检索得到：

- RAG 是一种检索增强生成技术。（正确）
- FlagEmbedding 是文本向量模型。（相关但不是答案）
- 深度学习是一种机器学习方法。（几乎无关）

虽然已经找到了正确答案，但是后面的排序并不理想。

这时再交给 **Reranker**：

- (Query, Document) ==》Cross Encoder ==》 重新计算相关性

最终：

- RAG 是一种检索增强生成技术。（正确）
- 深度学习是一种机器学习方法。（几乎无关）
- FlagEmbedding 是文本向量模型。（相关但不是答案）

整个过程类似于：**Embedding负责"海选"，Reranker负责"决赛"**

在实际开发 RAG 中通常采用：

- Embedding ==》Top-K ==》Reranker ==》最终答案

这种两阶段检索方案。

### 3. 核心特点

**开源与高性能**：提供了多个高质量的开源嵌入模型（如 `BGE`系列），这些模型在多项权威评测（如 MTEB）中达到了世界领先水平，甚至媲美 OpenAI 的付费接口

**功能全面**：不仅支持最基础的**文本向量化**，还支持以下高级功能：

- **检索**：为知识库文档生成向量，并通过语义搜索快速找到与问题最相关的文档片段。
- **语义相似度计算**：比较两段文本的语义相关性
- **文本重排序（Reranker）**：对检索到的多个结果进行精细化的相关性排序，显著提升 RAG 系统的准确性

**易于使用**：提供了简洁明了的 API，只需几行代码即可完成复杂的嵌入任务，并提供了本地部署方案，保障数据隐私和安全

### 4. 核心模型

FlagEmbedding 中最常使用的是 **BGE（BAAI General Embedding）** 系列模型。

| 模型               | 作用           |
| ------------------ | -------------- |
| BGE-base-zh        | 中文 Embedding |
| BGE-large-zh       | 中文高性能版本 |
| BGE-base-en        | 英文 Embedding |
| BGE-reranker-large | 文本重排序     |

实际开发中：

- 中文项目一般选择 **BGE-base-zh**。
- 对检索效果要求更高时使用 **BGE-large-zh**。
- 如果希望进一步提升答案质量，再增加 **BGE-reranker-large**。

因此，一个完整的 RAG 系统通常会同时使用：**Embedding模型 + Reranker模型**

二者职责不同，但互相配合。

文档：【https://github.com/FlagOpen/FlagEmbedding/blob/master/README_zh.md】

### 6. FlagEmbedding 与 Transformers 的关系

```
Transformers
      │
      ├── 提供底层模型加载能力
      │
      ▼
FlagEmbedding
      │
      ├── 封装 Embedding
      ├── 封装 Reranker
      └── 提供检索相关 API
```

也就是说：

- **Transformers 更底层、更通用。**
- **FlagEmbedding 更偏向于语义检索和 RAG。**

如果只是做 RAG，通常直接使用 FlagEmbedding 即可，无需自己使用 Transformers 编写向量提取逻辑。

### 2. 向量检索

**步骤**：

- 加载文档向量
- 问题向量化
- 计算余弦相似度
- 排序
- top-k

整个过程就是 **Embedding 检索（召回）**。

**什么是召回？**

从整个知识库中找到所有可能相关的候选文档。

包含三个步骤：**计算相似度**（找到候选文档）、**粗排**（根据相似度排序）、**取 Top-K**（得到最终召回结果）

例如：100 万条文档，经过 Embedding，找到Top-10，这一步就是**召回。**

它强调的是：**尽量不要漏掉真正相关的文档。**

因此，召回更加关注：Recall（召回率），而不是排序是否最准确。

### 3. 重排序（Reranker）

**为什么需要 Reranker？**

`Embedding` 快，但是排序不够精准。

因此通常只负责召回，真正决定最终顺序的是：Reranker

**什么是粗排（Coarse Ranking）？**

Embedding 检索：

- 计算向量相似度 ==》 排序 ==》Top-K

这一过程称为：**粗排（Coarse Ranking）**。

特点：

- 快
- 能处理海量数据
- 精度一般

**什么是精排（Fine Ranking）？**

Reranker：会重新计算 (Query, Document) 之间真正的相关程度。因此：

- 粗排 ==》 Top-K ==》 Reranker ==》 精排

**Reranker 的工作原理**

Reranker 使用的是：Cross Encoder

与 Embedding 最大区别：

Embedding：两个文档彼此独立编码，分别向量化，然后计算余弦相似度

 Reranker：(Query, Document) ==》 一起输入 Transformer ==》 通过注意力机制计算相关性 ==》 输出一个相关性分数

由于 Query 和 Document 在编码阶段就发生交互，因此得到的相关性分数通常更加准确。

**步骤**：

- 加载文档向量
- 获取原始文档和向量化数据
- 设置测试问题
- 加载向量化模型
- 问题向量化
- 计算余弦相似度
- 排序（粗排获取并存储召回结果）
- 对召回的结果重排序（精排）
    - 加载重排序模型
    - 把问题和召回的文档进行包装
    - 调用重排序方法 -- 计算得分`compute_score()`

```python
"""

from FlagEmbedding import FlagReranker

reranker = FlagReranker(
    model_name_or_path=r"G:\models\bge-reranker-large",
    use_fp16=True
)

reranker_input = [(question, doc) for doc in retriever_re]

scores = reranker.compute_score(reranker_input)
print(scores)
```

# 二、Sentence-Transformers

## （一）什么是Sentence-Transformers

### 1. 定义

**Sentence-Transformers** 是一个基于 **PyTorch** 的 Python 开源库，专门用于生成**句子、段落甚至图像的密集向量表示（Embeddings）**。

它的核心目标是：

- 将自然语言文本转换为计算机可以理解的高维向量；
- 通过向量之间的距离或相似度，判断文本之间的语义关系。

与传统 NLP 模型不同：

- 传统模型（如 Word2Vec）主要生成**单词级别向量**；
- Sentence-Transformers 专注于生成**句子级、段落级语义向量**，能够理解完整文本的语义。

### 2. 核心特点

#### （1）专为文本嵌入优化

Sentence-Transformers 对 Transformer 模型（如 BERT、RoBERTa 等）进行了进一步优化，使其能够生成适合语义比较的向量。

原始 Transformer 模型输出的是 Token 级别隐藏状态，需要额外处理才能表示整个句子。

Sentence-Transformers 通过：

- Transformer 编码；
- Pooling（池化）操作；

将整个文本转换为固定维度的句向量。

例如：输入【"苹果公司由乔布斯创建"】==》 模型编码 ==》 输出：【[0.123, -0.234, 0.567, ...]】

#### （2）基于 Transformer 架构

Sentence-Transformers 底层依赖 Transformer 模型，例如：

- BERT、RoBERTa、DistilBERT、BGE

通过训练优化，使模型生成的向量具有更好的：

- 语义相似度能力；信息检索能力；文本匹配能力。

#### （3）简单易用

只需要几行代码即可完成：

- 文本向量化；相似度计算；语义搜索；文本聚类。

无需手动处理：

- tokenizer；模型加载；pooling；向量归一化。

#### （4）丰富的模型库

Sentence-Transformers 提供大量预训练模型：

| 模型                                    | 适用场景                 |
| --------------------------------------- | ------------------------ |
| `all-MiniLM-L6-v2`                      | 英文语义相似度，小巧快速 |
| `paraphrase-multilingual-MiniLM-L12-v2` | 多语言语义匹配           |
| `BAAI/bge-base-zh-v1.5`                 | 中文检索、RAG            |
| `BAAI/bge-large-zh-v1.5`                | 中文高精度检索           |
| `msmarco-distilbert-base-v4`            | 英文搜索任务             |

### 3. 支持功能

Sentence-Transformers 主要用于：

#### （1）句子嵌入（Sentence Embedding）

将文本转换为向量：

- 文本 ==》 Sentence-Transformers ==》 Embedding Vector

#### （2）语义相似度计算

通过计算两个文本向量之间的距离，判断语义是否接近。

#### （3）语义搜索

用于 RAG 知识库检索：

流程：

- 用户问题 ==》 问题向量化 ==》与知识库文档向量计算相似度 ==》返回 Top-K 相关文档

#### （4）文本聚类

根据文本向量距离，将语义相似的文本自动分组。

#### （5）文本重排序（Reranker）

虽然 Sentence-Transformers 主要用于 Embedding，但也支持部分重排序任务。

常见流程：

- Embedding模型 ==》 快速召回 Top-K 文档 ==》Reranker模型 ==》 精准排序

SentenceTransformer 是核心模型加载类。

它负责：

- 文本编码；

### 3. 加载模型

| 参数                 | 作用               |
| -------------------- | ------------------ |

```python
device="cuda"
```

### 4. 文本向量化

```python
embeddings_1 = model.encode(
    documents,
    normalize_embeddings=True
)
```

`encode()` 方法用于：将文本转换为 Embedding 向量。

`normalize_embeddings=True`：将向量进行归一化，使向量长度变为 1。

```python
similarity = embeddings_1 @ embeddings_2.T
```

这里使用矩阵乘法计算相似度。

因为当向量已经归一化：
$$
A \cdot B = cos(A,B)
$$
所以：点积结果 ≈ 余弦相似度。

```python
scores.sort(
    key=lambda x:list(x.values())[0],
    reverse=True
)
```

作用：按照相似度从高到低排序。

# 三、Transformers

## （一）什么是 Transformers

### 1. 定义

**Transformers** 是由 Hugging Face 开发的一个开源深度学习工具库，主要用于加载、训练和推理基于 Transformer 架构的预训练模型。

它提供了一套统一的 API，可以方便地使用各种自然语言处理（NLP）、计算机视觉（CV）以及多模态任务中的大模型，例如：

- BERT、GPT、RoBERTa、T5、BGE、LLaMA 等

在知识库构建和 RAG 系统中，Transformers 主要用于：

- 加载预训练模型
- 加载 tokenizer
- 对文本进行编码
- 获取模型隐藏层输出
- 手动生成文本向量（Embedding）

### 2. 核心特点

#### （1）统一模型接口

Transformers 提供了统一的模型加载方式：

```python
AutoTokenizer.from_pretrained()
AutoModel.from_pretrained()
```

无需关心具体模型结构，只需要传入模型名称即可加载对应模型。

```python
tokenizer = AutoTokenizer.from_pretrained(
    "BAAI/bge-base-zh-v1.5"
)

model = AutoModel.from_pretrained(
    "BAAI/bge-base-zh-v1.5"
)
```

#### （2）支持大量预训练模型

Transformers 提供了大量已经训练好的模型：

| 模型  | 用途                      |
| ----- | ------------------------- |
| BERT  | 文本理解、分类、Embedding |
| GPT   | 文本生成                  |
| T5    | 文本转换任务              |
| BGE   | 文本向量化、语义检索      |
| LLaMA | 大语言模型生成            |

#### （3）提供完整模型组件

Transformers 主要包含以下几个核心组件：

| 组件      | 作用                             |
| --------- | -------------------------------- |
| Tokenizer | 将文本转换为模型能够理解的 Token |
| Model     | 加载 Transformer 网络            |
| Pipeline  | 快速调用模型完成任务             |
| Trainer   | 模型训练与微调工具               |

### 4. Tokenizer 文本编码

模型无法直接理解文本，需要先通过 tokenizer 将文本转换成 Token。

```python
text = "RAG（检索增强生成）是一种利用外部知识库来增强大模型回答能力的技术。"

encoded_input = tokenizer(
    text,
    padding=True,
    truncation=True,
    return_tensors="pt"
)

print(encoded_input)
```

参数：

| 参数                | 作用                 |
| ------------------- | -------------------- |
| padding             | 自动补齐长度         |
| truncation          | 超过最大长度进行截断 |
| return_tensors="pt" | 返回 PyTorch Tensor  |

输出类似：

```python
{
 input_ids: tensor([[101, 784, 3221, ...]]),
 attention_mask: tensor([[1,1,1,...]])
}
```

- `input_ids`
    - 文本转换后的 Token 编号
- `attention_mask`
    - 标记哪些 Token 是有效内容

### 5. 封装得到文本向量数据

#### （1）模型推理获取隐藏向量

将 tokenizer 的结果输入模型：

```python
import torch

with torch.no_grad():
    output = model(**encoded_input)

print(output)
```

- `model(**encoded_input)`：将 input_ids、attention_mask 等参数传入模型
- `torch.no_grad()`：关闭梯度计算、节省显存、加快推理速度

模型输出包含 Transformer 每一层计算后的隐藏状态。

主要输出：last_hidden_state，表示每一个 Token 对应的向量

#### （2）获取文本向量（Embedding）

Transformer 原始输出的是 Token 级别向量。

如果需要用于语义搜索，需要转换成整个句子的向量。

**方法一：使用 CLS Token**

BERT 类模型通常使用第一个 Token：`[CLS] 我 喜欢 学习 NLP`

其中：[CLS]向量，代表整个句子的语义。

```python
sentence_embeddings = output.last_hidden_state[:,0]
```

**方法二：向量归一化**

为了方便计算余弦相似度，需要进行 L2 归一化：

```python
sentence_embeddings = torch.nn.functional.normalize(
    sentence_embeddings,
    p=2,
    dim=1
)
```

归一化后：

- 向量长度变为 1
- 可以直接计算余弦相似度

#### （3）封装

```python
# 封装得到文本向量数据 -- 将文本转换为向量
def get_em(texts):
    # 分词模型处理输入的文本 -- 文本分词
    # 使用 tokenizer 对输入的 sentences 进行分词和编码，将文本转换为模型能够处理的输入格式，并返回 PyTorch 张量。
    encoded_input = tokenizer(texts, padding=True, truncation=True, return_tensors='pt')

    # 计算文本（token）向量
    # 关闭梯度计算，使用模型对编码后的输入进行前向推理，得到模型输出。
    with torch.no_grad():
        model_output = model(**encoded_input)

        # 提取 CLS 向量：从模型输出中提取每个句子的 CLS Token 向量，作为整个句子的语义表示（Sentence Embedding）
        sentence_embeddings = model_output[0][:, 0]

        # 向量归一化：对每个句子向量进行 L2 归一化，使每个向量的长度为 1，便于后续计算余弦相似度
        return torch.nn.functional.normalize(sentence_embeddings, p=2, dim=1)
```

之后：

```
docs_em = get_em(documents)
```

即可得到：文本向量数据

### 6. 查询文本向量化

准备查询：

```python
query = "如何使用深度学习？"
```

转换为向量：

```python
query_em = get_em([query])
```

得到：query向量

### 7. 计算文本相似度

计算查询向量和文档向量之间的相似度：

```python
cos_sim = torch.matmul(
    docs_em,
    query_em.T
)
print(f"相似度：{cos_sim}")
```

因为：

之前已经进行了 L2 归一化：

所以：向量点积 = 余弦相似度

### 8. 获取检索结果

```
scores = [
    {
        index: round(item[0],2)
    }
    for index,item in enumerate(cos_sim.tolist())
]

print(scores)
```

其中：相似度越高，说明文本语义越接近。

### 9. 总结

Transformers 生成文本向量流程：

- 文本 ==》 Tokenizer ==》 Token ==》 Transformer模型 ==》Hidden States ==》 池化(Pooling) ==》 Sentence Embedding ==》 余弦相似度计算 ==》 语义检索
