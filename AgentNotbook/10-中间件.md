# 一、中间件

LangChain 1.0 引入的中间件（`Middleware`）机制，本质上是一种非侵入式的扩展设计。它允许开发者在不修改 Agent 核心底层代码的前提下，像搭积木一样，在 Agent 执行流程的特定节点插入自定义逻辑。

## （一）核心

这种机制主要解决了 Agent 在实际应用中面临的三大核心痛点：**上下文管理、安全合规以及流程的可靠性**。

**首先**，在上下文管理方面，中间件能够动态地构建和优化输入给大模型的信息。

例如，当对话历史过长导致超出 Token 限制时，摘要中间件可以自动压缩历史消息；或者在每次模型调用前，动态修剪无关的工具调用记录，从而防止上下文过长导致模型“跑偏”。

**其次**，在安全与合规方面，中间件充当了强大的安全护栏。

它可以在模型处理信息的前后，自动检测并处理个人身份信息（PII）等敏感数据，支持脱敏、模糊化或直接阻断等策略。

同时，针对发送邮件、删除数据等高风险操作，人工审批中间件可以强制暂停执行，等待人类确认，从而保障系统安全。

**最后**，在流程控制与容错方面，中间件极大地提升了 Agent 的稳定性。

它内置了自动重试和模型降级机制，当主模型不可用或工具调用因临时错误失败时，系统能自动切换备用模型或重新尝试。

此外，它还能对模型或工具的调用次数进行严格限制，防止死循环或资源滥用。

**总而言之**，LangChain 的中间件将原本需要大量自定义代码才能实现的复杂逻辑（如日志记录、权限校验、状态监控等）进行了标准化和模块化，让构建生产级、高可控的 AI Agent 变得更加简单和优雅。

# 二、内置中间件

## （一）`ModelCallLimitMiddleware` 中间件

`  ModelCallLimitMiddleware` 是一个用于限制  应用中模型调用次数的中间件组件。它通过拦截和计数模型调用，实现对资源使用的控制和保护。

### 1. 应用场景

**API 资源控制**

在企业中，特别是当多个用户或系统通过 API 调用模型时，可能需要控制每个用户或系统在特定时间段内的调用次数。这可以避免过度调用导致的资源浪费或性能下降。例如，使用 `ModelCallLimitMiddleware` 限制每个用户每天最多可以调用模型 100 次，超出次数则拒绝服务。

**防止滥用**

企业的 AI 模型接口可能会遭到滥用或恶意攻击。例如，用户可能试图通过大量频繁的请求来进行压力测试。使用 `ModelCallLimitMiddleware` 可以有效限制每个会话或 IP 的请求次数，避免恶意攻击对系统的影响。

**`thread_limit` 参数**

`thread_limit` 是 `ModelCallLimitMiddleware` 中用于控制 *单个对话线程内* 模型调用次数的关键参数

```python
model_limit = ModelCallLimitMiddleware(
    thread_limit=1, # 限制次数
    exit_behavior="end", # 达到限制次数后，结束对话
)
```

### 2. 创建智能体

```python
from langchain.agents.middleware import ModelCallLimitMiddleware
from langgraph.checkpoint.memory import InMemorySaver

# 限制模型访问次数

    thread_limit=1, # 限制次数
    exit_behavior="end", # 达到限制次数后，结束对话
)

    model, tools,
    system_prompt=prompt,
    middleware=[model_limit],
    debug=True  # 可选，一般用于调试，生成环境必须设置为false
)
```

## （二）`HumanInTheLoopMiddleware` 中间件

`HumanInTheLoopMiddleware` 是 LangChain 1.0 提供的一个**内置中间件**，它的核心作用是为智能体的工具调用引入**人工审核机制**，在自动化流程中增加人类监督环节

### 1. 核心概念

`HumanInTheLoop (HITL)`是一种人机协作模式，在智能体执行关键操作（如发送邮件、执行SQL、转账等）前，暂停执行并等待人类审核批准。这种模式特别适用于：

- **高风险操作**：需要人工确认才能执行
- **敏感数据访问**：访问隐私信息前需审批
- **错误预防**：避免AI误操作
- **合规要求**：满足监管合规需求

### 2. 工作流程

```
用户请求
    ↓
智能体决定调用工具
    ↓
【HumanInTheLoopMiddleware 拦截】
    ↓
返回中断状态 (__interrupt__)
    ↓
人类审核者查看并决策
    ↓
├─ 批准 (approve) → 执行工具
├─ 编辑 (edit)    → 修改工具参数后执行
└─ 拒绝 (reject)  → 不执行，返回原因
    ↓
恢复执行并返回结果
```

### 3. 参数说明

定义人工审核中间件

```python
HumanInTheLoopMiddleware(

    interrupt_on={

            "allowed_decisions": ["approve", "reject", "edit"],  # 允许的操作：批准、拒绝、编辑
            "description": "邮件发送需要人工审核，请确认邮件内容是否正确",  # 自定义提示
        }
    },
    escription_prefix="【人工审核】"  # 公共提示前缀
)
```

# 三、自定义中间件

在 `LangChain` 中，中间件（`Middleware`）是一种非常灵活的机制，允许开发者在模型调用的不同阶段插入自定义逻辑。通过中间件，您可以对模型的输入、输出、处理流程等进行精细控制，从而满足特定的需求

```
用户输入 
    ↓
【before_agent】 ← 第一个执行！(仅一次) Agent启动前
    ↓
before_model (每次模型调用前)
    ↓
【模型实际调用】
    ↓
after_model (每次模型调用后)
    ↓
【可能多次循环】
    ↓
after_agent (Agent结束后 执行一次) 最后执行！
    ↓
最终输出
```

## （一）核心作用

自定义中间件的作用主要包括以下几个方面：

- **在模型调用前和后插入逻辑**：
    - 您可以使用中间件
    - 在模型**调用前**执行某些操作（例如，验证用户输入、记录日志、缓存查询结果等）
    - 在模型**调用后**执行其他操作（例如，修改输出、格式化响应、记录调用数据等）。
- **增强功能的解耦性和可重用性**：
    - 通过中间件，您可以将功能模块化、解耦，并使其易于复用
    - 例如，身份验证、敏感词过滤、错误处理等可以通过不同的中间件来实现，而不影响主要的业务逻辑。
- **精细化控制**：
    - 通过中间件，您可以实现对模型调用的细粒度控制
    - 如：限制请求次数、管理模型负载、插入特定的预处理和后处理逻辑等。

## （二）`before_model`装饰器

### 1. 定义

`before_model` 是 `LangChain` 中一个非常重要的装饰器，它允许开发者在每次调用模型之前插入自定义逻辑。该钩子接收 `AgentState` 和 `Runtime` 两个参数，并返回模型的输入（或者修改后的输入）。如果您在此钩子中抛出异常，模型的调用将会被阻止。

### 2. 参数

```
@before_model
def before_model_hook(state: AgentState, runtime: Runtime) -> dict:
    # 自定义处理逻辑
    return None
```

**state（AgentState）**：

- `state` 是一个 `AgentState` 对象，包含代理（Agent）的当前状态。
- 它通常包含以下信息：
    - 当前的输入（例如，用户的消息）。
    - 当前代理正在执行的任务状态、工具等。
    - 可能还包含代理执行过程中的历史数据或状态。

**runtime（Runtime）**：

- `runtime` 是与当前模型执行相关的运行时环境信息。它通常包含请求的元数据、运行时间等动态信息。
- `runtime` 提供了模型调用过程中与环境相关的上下文信息。

### 3. 常见用途

**输入验证**：检查输入是否符合某些条件（例如，敏感词过滤、输入长度检查、是否包含特定关键词等）。

**日志记录**：记录每次模型调用之前的状态，例如用户输入、调用时间等。

**缓存检查**：在模型调用之前检查缓存，如果数据已缓存，则直接返回缓存结果，避免不必要的计算。

**资源控制**：比如限制每个用户的请求频率，防止滥用。

## （三）`after_model` 装饰器

### 1. 定义

`after_model` 是 `LangChain` 提供的一个装饰器，用于在模型调用之后对响应进行处理。与 `before_model` 不同，`after_model` 允许开发者在模型响应后执行一些后处理操作。它为开发者提供了一个机会，可以对模型返回的结果进行修改、记录、分析等操作。

### 2. 应用场景与核心作用

| 应用场景              | 核心作用                                               | 典型示例                                                     |
| --------------------- | ------------------------------------------------------ | ------------------------------------------------------------ |
| **1. 监控与日志记录** | 无侵入地记录模型的行为和性能，是调试和监控的"记录仪"。 | • **记录响应日志**：将模型返回的内容打印或保存到文件，方便追踪问题 [-1](https://docs.langchain.com/oss/python/langchain/middleware/custom)[-6](https://www.e-com-net.com/article/2017015330852888576.htm?__cf_chl_tk=_Br0aDabthzBtUdDsDZz_.16lWXE_mv9t0tseJcRhvU-1769730001-1.0.1.1-lm1qvcgEj2GRzcztgMJWWZGVYdCfWVfWxq2EY0s5ANc)。• **性能监控**：记录每次模型调用的耗时和token消耗，用于成本分析和性能优化 |

## （四）案例：敏感词验证

### 1. 自定义中间件

导入所需库：

```
import re
from langchain.agents.middleware import before_model, AgentState, after_model
from langchain_core.messages import AIMessage
from langgraph.runtime import Runtime
```

通过装饰器 before_model  自定义中间件  `WordFilterMiddleware` （单词过滤中间件）

功能：若问题中包含敏感词汇，拦截

```python
@before_model
def WordFilterMiddleware(state:AgentState,time:Runtime):
    print("验证是否在模型调用之前执行")
    print(state)
    # 用户问题
    que = state["messages"][0].content
    # 查询数据库或者查询外部文件
    word_list = ["赌博","嫖娼","吸毒"]
    for w in word_list:
        if w in que:
            raise ValueError(f"问题中内容包含敏感词{w}，不允许生成")
    return time
```

- `raise` -- Python 中用于主动触发异常的指令
- `ValueError` -- 值错误，一个内置的异常类，专门用于表示“传入了不正确的值或参数”
- 两者结合的作用 -- **在代码中检测到非法数据时，强制中断当前程序的正常执行流程，并抛出明确的错误提示**

通过装饰器 after_model  自定义中间件  `WordPingMiddleware` （单词替换中间件）

功能：若模型回复中有敏感词汇，用特殊字符替换

```python
@after_model
def WordPingMiddleware(state:AgentState,time:Runtime):
    print("验证是否在模型调用之后执行")
    print(state)
    # AI回复内容
    ai_msg = state["messages"][1].content
    # 查询数据库或者查询外部文件
    word_list = ["赌博","嫖娼","吸毒"]
    change_msg = ai_msg
    for w in word_list:
        if w in change_msg:
            # 获取过滤内容
            change_msg = re.sub(w,"$$$",change_msg)
    if change_msg != ai_msg:
        return {
            "messages": [AIMessage(content=change_msg)]
        }
    # 没有任何修改
    return {}
```

- `re.sub(a, b, c)` -- 使用正则表达式在字符串 `c` 中查找所有匹配模式 `a` 的内容，并将它们全部替换为字符串 `b`，最后返回替换后的新字符串。

```python
@after_model
def ModelCallLimitAfterMiddleware(state:AgentState,time:Runtime):
    user_id = time.execution_info.thread_id
    print(f"用户id:{user_id}")
    # 自定义键名
    key = f"limit:{user_id}"
    # 设置自增
    client.incr(key,1)
    # 设置失效事件
    client.expire(key,300)
    print(f"用户{user_id}模型使用次数增加1")
    return {}
```

- `client.incr(key,1)` -- `INCR`（自增）包含了“读取当前值”、“加 1”、“写回新值”三个动作
    - 在 `Redis` 中以原子操作的方式
    - 将指定键（key）对应的数值安全地加 1（若键不存在则自动初始化为 0 后再加 1）
    - 从而精准记录当前用户的模型调用次数

## （六）`before_agent` 装饰器

### 1. 定义

`before_agent` 是 LangChain 1.0 中间件系统中的**节点式钩子**之一，它在**整个Agent执行的最开始**触发，是整个Agent生命周期的第一个钩子

### 2. 应用场景与核心作用 

| 应用场景                    | 核心作用                                                     | 典型示例                                                     |
| --------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| **1. 全局初始化与资源准备** | 在 Agent 开始工作前，准备好所有必要的资源和环境[-5](https://blog.csdn.net/Yunyi_Chi/article/details/157945279)。 | • **加载全局配置**：从配置文件或环境变量中读取设置（如API密钥、模型参数）[-5](https://blog.csdn.net/Yunyi_Chi/article/details/157945279)。• **初始化资源**：建立数据库连接、打开文件句柄、初始化缓存客户端[-5](https://blog.csdn.net/Yunyi_Chi/article/details/157945279)。• **设置全局状态**：在`AgentState`中注入用户ID、会话ID等上下文信息[-1](https://docs.langchain.com/oss/python/langchain/middleware/custom)。 |
| **2. 环境与权限检查**       | 在执行核心逻辑前，验证运行环境和用户权限，确保流程可以安全启动[-5](https://blog.csdn.net/Yunyi_Chi/article/details/157945279)。 | • **检查环境变量**：验证必要的环境变量（如`API_KEY`）是否已设置，避免后续调用失败[-5](https://blog.csdn.net/Yunyi_Chi/article/details/157945279)。• **用户身份验证**：检查用户是否有权限执行此Agent[-5](https://blog.csdn.net/Yunyi_Chi/article/details/157945279)。• **限流预检查**：检查用户调用次数是否已达上限，提前拦截非法请求。 |
| **3. 输入预处理与验证**     | 对用户的输入进行清洗、转换或验证，为后续模型调用准备高质量的数据。 | • **输入格式校验**：验证用户输入是否符合预期格式（如JSON、特定关键词）。• **输入标准化**：将用户输入统一转换为小写、去除多余空格等 |

### 3. 参数

```
@before_agent(can_jump_to=["end"])
def log_before_agent(state: AgentState, runtime: Runtime) -> dict:
    print("正在调用智能体...")
    print(f"问题内容是：{state["messages"][0].content}")
    if  "赌博" in state["messages"][0].content:
        print("问题内容包含敏感词")
        raise ValueError("输入包含不允许的敏感词，请修改后重新提问。")
    return  None
```

可选参数：`can_jump_to`，默认是 end

`before_agent` 可以配置允许跳转的目标节点，可用跳转目标：

- `"end"`：直接结束Agent执行
- `"tools"`：跳转到工具执行节点
- `"model"`：跳转到模型调用节点

## （七）`after_agent` 装饰器

### 1. 定义

在 `LangChain 1.0` 中，`after_agent` 是一个装饰器，主要用于在 `Agent` 完成执行（即模型调用过程结束后）之后执行自定义的操作。它允许开发者在整个代理执行流程结束时插入一些后处理逻辑。这与 `after_model` 类似，但是 `after_agent` 钩子是针对整个代理的执行过程，而不仅仅是模型调用

### 2. 应用场景与核心作用

| 应用场景                  | 核心作用                                         | 典型示例                                                     |
| ------------------------- | ------------------------------------------------ | ------------------------------------------------------------ |
| **1. 资源清理与状态重置** | 执行必要的清理工作，避免状态污染影响下一次调用。 | • **释放临时资源**：关闭在Agent运行中打开的文件句柄或数据库连接[-3](https://blog.csdn.net/Yunyi_Chi/article/details/157945279)。• **重置运行状态**：清理线程局部变量，或重置用于单次运行的计数器[-1](https://docs.langchain.com/oss/python/langchain/middleware/custom)。 |
| **2. 全局日志与监控**     | 记录 Agent 运行的最终结果和整体性能指标。        | • **记录最终响应**：将 Agent 的最终答案保存到数据库或日志文件中[-3](https://blog.csdn.net/Yunyi_Chi/article/details/157945279)。• **性能指标统计**：计算整个 Agent 运行的总耗时、调用的模型次数、调用的工具次数等[-3](https://blog.csdn.net/Yunyi_Chi/article/details/157945279)。 |
| **3. 最终输出处理**       | 对 Agent 生成的最终答案进行统一的后处理。        | • **统一格式封装**：将 Agent 的文本输出包装成特定的 JSON 结构，方便前端展示[-3](https://blog.csdn.net/Yunyi_Chi/article/details/157945279)。• **敏感信息全局过滤**：在最终输出前，再执行一次全局的敏感词过滤，确保万无一失。 |

### 3. 特点

**只执行一次**：无论Agent内部循环多少次，`after_agent` 只执行一次

**最后执行**：是所有钩子中最后一个执行的

**无法跳转**：`after_agent` 不支持 `jump_to`，因为Agent已经结束

### 4. 参数

```
@after_agent
def handler(state: AgentState, runtime: Runtime) -> dict[str, Any] | None:
    """
    Args:
        state: Agent的最终状态（包含完整的对话历史）
        runtime: 运行时上下文（会话ID、配置信息、元数据等）
    
    Returns:
        dict | None: 返回字典会更新最终状态，返回None表示无修改
    """
```

## （八）案例：权限校验和token统计

### 1. 自定义中间件

导入所需库：

```
from langchain.agents.middleware import AgentState, after_agent, before_agent
from langgraph.runtime import Runtime

from tool.query_employee_tool import QueryEmployeeTool
```

通过装饰器 before_agent  自定义中间件  `PermissionCheckMiddleware` （权限校验，判断当前用户是否有资格/权限）：

```python
@before_agent
def PermissionCheckMiddleware(state:AgentState,time:Runtime):
    # 用户id
    user_id = time.execution_info.thread_id
    # 演示案例，在数据库中查询
    result = QueryEmployeeTool.invoke({
        "sql":f"select department from employee where user_id = '{user_id}'"
    })
    # 获取部门
    department = result[0]['department']
    # 只有管理员，可以访问
    if department != "管理员":
        raise Exception(f"用户{user_id}没有权限访问")
    return {}
```

如果从数据库中获取到的结果为字符串，则需要转换为适合的格式

- `ast.literal_eval()` -- 将包含 Python 字面量（如列表、字典、字符串等）的字符串安全地解析并转换为真实的 Python 对象

```
import ast
data = ast.literal_eval(result)
```

- `QueryEmployeeTool.invoke({})` -- 为什么用`invoke`
    - `invoke()` 就是 `Runnable` 协议中**最标准的同步执行入口**
    - LangChain 的设计哲学是“万物皆可调用”，无论是大模型（LLM）、提示词模板（Prompt）、输出解析器（Parser），还是写的工具（Tool），它们底层都实现了 `Runnable` 接口
    - 这意味着它们都共享一套标准的调用方法
        - `invoke()`：同步调用
        - `ainvoke()`：异步调用（用于高并发场景）
        - `stream()`：流式调用（用于打字机效果）
        - `astream()`：异步流式调用
    - 当执行这行代码的时候：
        - 将传入的字典 `{"sql": ...}` 自动拆解成工具函数所需的参数
        - 调用定义工具时绑定的那个 Python 函数（比如执行 SQL 查询）
        - 将查询结果按照 LangChain 的标准格式返回
    - 所有调用方式，不是必须用`invoke`：
        - 最标准的：`invoke()`、`ainvoke()`、`stream()`、`astream()`
        - 传字典：`QueryEmployeeTool({"sql": "..."})`
        - 直接传入字符串：`QueryEmployeeTool("select department from employee where user_id = '4'")`
        - 老版本：`QueryEmployeeTool.run({"sql": "..."})`

通过装饰器 after_agent  自定义中间件  `CountTokenMiddleware` （将用户模型调用次数自增一次） -- 单次对话：

@after_agent()

通过装饰器 after_agent  自定义中间件  `CountTokenMiddleware` （将用户模型调用次数自增一次） -- 多轮对话：

```python
@after_agent()
def CountTokenMemoryMiddleware(state:AgentState,time:Runtime):
    # 用户id
    user_id = time.execution_info.thread_id
    # 自定义键名
    key = f"countToken:{user_id}"
    # 获取键的值
    value = client.hgetall(key)
    # 计算token
    token = 0
    # 从redis中获取token，不存在设置为0，存在直接取出
    if not value:
        input_tokens = 0
        output_tokens = 0
        total_tokens = 0
        client.hset(key, "input_tokens", input_tokens)
        client.hset(key, "output_tokens", output_tokens)
        client.hset(key, "total_tokens", total_tokens)
    else:
        print("开始从redis中取值")
        input_tokens = int(client.hget(key, "input_tokens").decode())
        output_tokens = int(client.hget(key, "output_tokens").decode())
        total_tokens = int(client.hget(key, "total_tokens").decode())
    # 或取本轮对话所消耗的token值，加上以前的值后再存入redis
    usage_metadata = state['messages'][-1].usage_metadata
    if usage_metadata:
        print(usage_metadata)
        input_tokens += usage_metadata['input_tokens']
        output_tokens += usage_metadata['output_tokens']
        total_tokens += usage_metadata['total_tokens']
        token += input_tokens + output_tokens + total_tokens
        print(f"用户累计消耗token:{total_tokens}")
        # 将新值存入redis中
        client.hset(key, "input_tokens", input_tokens)
        client.hset(key, "output_tokens", output_tokens)
        client.hset(key, "total_tokens", total_tokens)
        return {
            "messages": [AIMessage(content=f"输入token:{input_tokens}，输出token:{output_tokens}，总token:{total_tokens}")]
        }
    return {}
```

- `client.hgetall(key)` -- 为什么不用get
    - `client.get(key)` —— 对应 String（字符串）类型
        - 如果用 `get` 和 `set`，Redis 会把整个数据当成**一整个字符串**来存取
        - 如果想存多个维度的数据（比如 `input_tokens`、`output_tokens`），必须把它们打包成一个 JSON 字符串存进去，取出来后再解析，非常麻烦
    - `client.hgetall(key)` —— 对应 Hash（哈希/字典）类型
        - `client.hset(key, "input_tokens", input_tokens)`：往一个**哈希表**里写入一个键值对
        - 它就像一个 Python 字典，可以非常方便地分类存储多个字段，并且可以单独修改某一个字段，而不影响其他字段
    - 因为用的是 `hset`（往哈希表里存数据），所以取数据时必须用 `hgetall`（获取整个哈希表）或 `hget`（获取哈希表中的某个字段）
    - 如果用 `client.get()` 去取一个 Hash 类型的数据，Redis 会直接报错：`WRONGTYPE Operation against a key holding the wrong kind of value`（类型不匹配）
    - `get/set` 是用来存取**一整块字符串**的；`hgetall/hset` 是用来存取**字典（键值对集合）**的
